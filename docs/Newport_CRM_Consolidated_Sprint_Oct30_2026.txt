CONTRACTS / BUSINESS RULES
1. Acquisition STATUS is distinct from STAGE. Active and Pending are in-progress. Completed is finalized and should align to Closing (enforce or flag contradictory combinations after inspecting existing state, without silently overwriting historical records). Inactive, Declined, Withdrew, and Closed remain stored and filterable, but do not contribute to active/pending action alerts. Respect the existing meaning of Closed separately from Completed.
2. Needs Attention is computed ONLY for Active and Pending opportunities. Use unfinished tasks linked by stable opportunity ID: overdue task = red warning; due today or within the next 7 calendar days = navy warning; zero unfinished linked tasks = red warning for missing follow-up. No warning for Completed or other inactive statuses, regardless of stale task dates. A deal can have multiple tasks and one warning; counts are UNIQUE deals, not task counts. Counts of overdue tasks are counts of unfinished overdue TASKS, not unique deals. A deal's displayed Next Action is the earliest-due unfinished linked task; tie-break deterministically (priority A/B/C, then ID). Tasks with missing dates sort after dated ones and require validation for new tasks. Show only one canonical task for the next action while retaining all unfinished tasks in the opportunity profile.
3. A task's overdue indicator is red; an unfinished task due today or in the next 7 days (but not overdue) is navy. On Track means not overdue. Completed/archived tasks do not count as unfinished. Preserve the existing 7-day Done-to-History transition and immediate confirmed X-to-History workflow; permanent deletion never enters History.
4. Everywhere a save, deletion, task status, document change, relationship edit, or deal edit happens, all applicable selectors, charts, counts, profile sections, notifications and history must derive from the same persisted state; no copy-pasted independent mock lists. Write the activity log only after successful commits. Keep Save Changes disabled until a real mutation exists.
5. Date comparisons must use the user-local calendar day (not UTC midnight causing off-by-one). Use real current date dynamically, not a fixed 2026 calendar date. The requested planning reference for refreshed fictional starter data is OCTOBER 30, 2026; it must still behave correctly after that day.
